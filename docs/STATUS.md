Feed-`delete` (Tombstone und Revoke sind auf der API gleich) entfernt Entitaet und lokal den Unterbaum; Wiederfreigabe kommt als Upsert. Upserts mit kleinerer Version als lokal werden ignoriert.

Folge-Mutationen auf dieselbe Entitaet (`chained`) nehmen die Version zur Sendezeit aus dem bestaetigten Stand. `version_conflict` => Status `conflict`, Folgemutationen derselben Entitaet warten, Anzeige zeigt Serverstand; `resolveConflict(keepMine:)` sendet erneut auf aktueller Version bzw. verwirft. `mutation_id_reused` => einmal mit neuer `mutationID` (die alte war nachweislich nicht unsere), danach `rejected`. 403/404/400/409 (`id_exists`, `id_deleted`, `project_cycle`) => `rejected` (App zeigt Hinweis und verwirft). `unauthorized` wird geworfen.
