Sichtbarer Stand = bestaetigt + ausstehende Mutationen (optimistisch, `snapshot()`).
- Cursor: Start `c0`; bei `c0` werden alle Seiten (`hasMore`) gesammelt und in einem Commit ersetzend uebernommen; sonst seitenweise Commit mit neuem Cursor. 409 `cursor_ahead` und 400 `invalid_cursor` => Vollabgleich ab `c0` (Warteschlange bleibt). Feed-`delete` (Tombstone und Revoke sind auf der API gleich) entfernt Entitaet und lokal den Unterbaum; Wiederfreigabe kommt als Upsert. Upserts mit kleinerer Version als lokal werden ignoriert.
- Warteschlange: Client-IDs, je Mutation `mutationID`; Senden strikt in Reihenfolge vor dem Pull; Wiederholung nach Transport-/5xx-Fehler mit derselben `mutationID` (offline => Pull entfaellt). Folge-Mutationen auf dieselbe Entitaet (`chained`) nehmen die Version zur Sendezeit aus dem bestaetigten Stand. `version_conflict` => Status `conflict`, Folgemutationen derselben Entitaet warten, Anzeige zeigt Serverstand; `resolveConflict(keepMine:)` sendet erneut auf aktueller Version bzw. verwirft. `mutation_id_reused` => einmal mit neuer `mutationID` (die alte war nachweislich nicht unsere), danach `rejected`. 403/404/400/409 (`id_exists`, `id_deleted`, `project_cycle`) => `rejected` (App zeigt Hinweis und verwirft). `unauthorized` wird geworfen.
